# ADM 管理系统项目汇报

> 面向手机数码 B 端交易与运营的一体化管理平台
> 汇报对象：公司管理层（非技术背景） | 报告日期：2026-08-01
> 内容依据：D:\work\jie\adm 仓库代码扫描

## 一、项目一句话定位

ADM 是一套把手机数码行业的 B 端批发、代发、交易撮合、履约发货、资金结算和经营分析串成一个闭环的业务管理系统。它既给采购公司一个“看货、报价、抢单、收货、付款”的线上交易市场，也给运营团队一套“管订单、管钱、管供应链、看利润”的中台工具。

## 二、老板最关心的 6 个问题（60 秒版）

1. 系统在做什么生意？手机数码产品的 B 端批发与一件代发：平台有货源订单，采购公司在线抢单拿货。
2. 业务走到哪一步了？已形成“发布订单→在线抢单→成交→串码/物流→发货签收→财务结算→售后”的完整闭环；仓库内已包含生产环境配置（阿里云数据库/缓存/消息队列、微信支付商户证书、正式域名）。
3. 谁在用这个系统？平台运营团队与下游采购公司/客户，两端各有独立界面、角色和权限。
4. 系统替人干了什么活？内置 19 个定时任务，覆盖订单下载、供应链同步、账单生成、物流监控、经营利润重算等场景，把大量人工操作变成自动化。
5. 系统和外面怎么连？已对接吉客云 ERP、快递100、微信（扫码/企业微信/支付）、e签宝、淘宝、旺店通、拼多多、阿里云 OSS、SN 序列号、RocketMQ 等。
6. 系统值钱在哪？它不是普通后台模板，而是沉淀了手机数码行业特有的业务规则：四级报价抢单、履约保证金、串码校验、平台二次销售校验、电子合同、按店铺/单品核算利润等。这些规则需要行内业务积累才能做出来。

## 三、业务架构

```
平台运营方（后台/运营管理端）
        │  发布订单、配置规则费率、审核、财务、分析、供应链
        ▼
┌────────────── 交易与运营平台 ──────────────┐
│  交易市场 → 订单履约 → 资金财务 → 经营分析   │
│  主数据 / 权限体系 / 供应链自动化 / 售后     │
└──────┬──────────────────────────┬─────────┘
       ▼                          ▼
 采购公司（业务操作端）          外部系统（吉客云、快递100、
  在线浏览/抢单/发货/收款        微信、电子签、淘宝/拼多多等）
```

核心业务主线：

> 运营方把货源需求变成“报价中订单”发布到交易市场；采购公司按品牌、省份城市、商品 SKU 浏览，按不同价位抢单；成交后系统进入履约流程，要求上传产品串码并做平台二次销售校验，随后发货、在途监控、签收确认；资金层面冻结保证金、在线充值、生成账单与付款计划，最后通过电子合同和发票完成商务闭环；每天经营分析模块自动把订单、退款、费用汇总成从“销售收入”到“经营利润”的利润账。

## 四、核心业务模块（做了什么）

### 4.1 交易市场：在线抢单撮合

- 首页即交易市场：按品牌 Tab、省份/城市、商品型号、SKU 逐级浏览“报价中”订单，实时显示可抢数量与收货地点。
- 四级报价机制：同一订单提供最高价、高价、低价、最低价四个价位，各自带抢单倒计时；出价后冻结履约保证金，被更高报价抢占会自动解冻；最低价出价立即成交。
- 抢单履约规则已在产品中固化：抢单临时扣除 50 元履约保证金；新订单须在当日 18:59 前上传串码和运单号，逾期取消并扣保证金；顺丰包邮微派服务、禁止到付；付款后 20 个工作日内开具 13% 增值税专用发票等。
- 技术保障：消息队列做延迟竞价事件，Redis 缓存热门榜单，保证多人同时抢单时数据一致。

### 4.2 订单全流程管理

- 三种业务形态：入仓（批量采购）、一件代发（O2O）、销售订单。
- 完整订单状态机：新建 → 待发布 → 报价中 → 发货中 → 当日发货 → 在途 → 待确认收货 → 已完成；另有追单、异常订单、撤销、售后等分支。
- 手机数码行业特有的履约控制：
  - 串码管理：IMEI/SN 录入、串码与 SKU 关系维护、发货前/发货后串码要求配置；
  - 平台二次销售校验：发货前校验串码在拼多多、京东、快手、抖音、淘宝/天猫等平台是否已被销售，防止“二销”纠纷；
  - 物流异常监控：24 小时无揽收、7 天未签收、手机号后四位错误、快递疑难件、拒收/拦截等自动识别；
  - 追单、退货、售后处理与确认收货闭环。

### 4.3 资金与财务一体化

- 企业资金账户：采购公司在线充值（微信 H5 支付）、可用资金管理、履约保证金冻结/解冻、资金流水全留痕。
- 账单与付款：入仓账单/代发账单、当日应付、付款计划、付款方（客户）配置、扣款管理、交易流水。
- 合同与发票：电子合同签署（e签宝）、合同状态自动同步、公司合同授权、发票管理。
- 收款管理：收款账户、收款详情；财务模块仅主账号可见，主账号/子账号权限隔离。

### 4.4 主数据管理

- 经营主体：从吉客云同步经营主体（公司主体、税号、联系人、地址等），支持停用/删除状态同步。
- 销售渠道：从吉客云同步渠道、平台、部门归属，支撑订单归属与经营分析。
- 经营主体银行账户与银行流水；商品/SKU 映射、商品管理、集中采购。

### 4.5 供应链自动化（吉客云 ERP 对接）

- 已封装吉客云开放平台能力：商品、订单、发货、退款、供应商、物流任务、库存/入库、销售单驳回等。
- 自动化任务：订单下载、在途流转、撤销/驳回、代发推单、供应商同步、物流任务同步。
- 物流能力：对接快递100 实现物流轨迹查询、轨迹订阅推送、电子面单。

### 4.6 经营分析：从收入到利润的自动核算

- 每日自动从吉客云同步订单（发货/修改）与退款数据到独立分析库（ana_* 表），支持按日重算。
- 利润指标链：销售收入 → 商品成本/商品激励 → 商品毛利 → 履约毛利 → 部门利润 → 经营利润。
- 费用全覆盖：平台服务费、物流费、推广/返利、罚款、损耗、税费、资金成本（回款天数 × 年化）、直接人工、部门成本、间接成本、仓储成本、其他调整。
- 平台服务费率支持按“平台 + 业务类型 + 品类”多级配置，自动匹配最细费率。
- 数据质量看板：自动识别未匹配经营主体、店铺、SKU、缺少评估成本的记录；费用配置支持 Excel 模板导入/导出。

### 4.7 系统与权限

- 标准 RBAC 权限体系：用户、角色、菜单、部门、岗位、字典、参数、通知，支持数据权限范围控制。
- 登录安全：账号密码 + 验证码、微信公众号扫码登录、企业微信扫码/授权登录（含企业微信用户每日同步）。
- JWT + Redis 会话、XSS 防护、接口统一异常与响应封装。

## 七、技术底座（简版）

- 架构：两个后端应用（运营后台 + 业务接口）、两个前端（运营管理端 + 业务操作端），共享一套领域模块，按 Controller → Biz → Facade → Service → Mapper 分层，职责清晰、可维护。
- 技术栈：Java 11、Spring Boot 2.6、MyBatis-Plus、MySQL、Redis、RocketMQ、Vue 2 + Element UI、EasyExcel、MapStruct。
- 工程质量：包含架构分层测试、Mapper XML 完整性测试、分析库隔离测试、经营分析计算测试等 27 个自动化测试用例。
- 项目规模：11 个后端模块、1238 个 Java 文件、76 个后端接口控制器、51 个 Mapper XML、19 个定时任务、26 份增量 SQL 脚本；前端约 460 个源码文件。

## 十、总结

一句话总结：这是一套按真实手机数码批发/代发业务设计、已具备生产运行条件的一体化“交易 + 履约 + 资金 + 分析”系统，不是概念原型。它最值钱的部分，是把行业里的抢单规则、串码校验、二次销售风控、保证金与利润核算这些“行内人才懂”的业务逻辑，全部变成了可运行、可维护、可扩展的软件资产。
